## What we have learned (details and numbers in LOG.md)

1. Recall depends mostly on batch size: fewer paragraphs per request,
   less skimming. Batch 16: 0.72-0.78; 4: 0.86-0.89; 1: 0.93. LTeX+
   (LanguageTool) 0.76, Harper 0.42.
2. flagcheck's edge is context-dependent grammar (agreement 45/55 at
   batch 4 vs LTeX+ 12/55). LTeX+ is better on a/an (25/25 vs ~18).
3. On clean published papers most flags from every tool are false
   (provisional labels). A single LLM pass over-corrects: "which obtains",
   "it increases" flagged as errors.
4. Voting fixes that. False flags are one-offs; real errors recur. Batch
   4 with 2-of-3: recall 0.88, 3.7 clean flags/1k (single run 6.7);
   3-of-3: recall 0.79, 1.0 flags/1k. LTeX+ tuned: 0.76, 10.4.
5. Unknown markup: on an invented format, LTeX+ and Harper flag the
   markup (42-178 flags/1k, mostly at markup); flagcheck stays at 7.6/1k
   (recall 0.89 -> 0.78). The hand-written mask removes only ~0.5
   flags/1k on LaTeX: the robustness comes from the model.
6. Harper has no LaTeX support and silently stops partway on 4/10 papers.
7. Thinking (adaptive) made checks 2-3x slower and in one test returned
   near-empty batches; kept off. Effort medium vs low: within noise.
8. Two blind Claude labellers agree well (kappa 0.77; 0.82 binary). All
   precision numbers are provisional until compared with the owner's
   labels.

## Direction

The paper's claim is shifting from "LLMs beat rule-based checkers" (does
not hold against LanguageTool on a single pass) to: a detection-only LLM
checker with small batches and voting finds more errors than
LanguageTool, especially grammar needing context, with a fraction of the
flags, and keeps working on markup no rule-based tool parses. Plus the
benchmark itself (first false-flag measurement on raw markup).

Weak spots reviewers will hit: synthetic injected errors, 10 papers,
LLM-provided labels, one model, single runs for some configurations.

## Decisions (why)

- Raw source to the model, mask afterwards: deterministic and testable.
- Batch 16 default kept for now; batch 4 recommended (owner to confirm).
- Voting not yet default: triples calls per check (owner to decide).
- Thinking off, effort medium: latency, and no measured loss.
- Shape filters (multi-word spelling, spelling-variety reasons, quotes
  over 6 words): each removed only false flags in pilots.
- Harper and LTeX+ get default and "tuned" configs (dialect with fewer
  flags + dictionary of words flagged at least twice in the clean paper),
  and the same markup filter, so baselines are not strawmen.
- Injection uses flagcheck's own mask to place errors (stated as a bias).

## Dead ends / bugs found

- arXiv OAI `created` is not the v1 date; use the YYMM in the identifier.
- inject.py v1 (site first, then operator) gave 90 % spelling errors.
- Harper on LaTeX reads plain text; LTeX+ CLI gives start positions only
  (use the language server).
- Waiting on a background run with `pgrep -f <pattern>` matched the wait
  loop itself; use the tool's background notification instead.
